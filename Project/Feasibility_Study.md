1.	Technical Feasibility

The system can be developed using the technologies we currently have, i.e., software that we will create using the available knowledge the team has required to design the system and display the intended fixtures for the community sports league.
The team currently has experience in web development, database management, and software engineering, which would prove to be beneficial for this project. The main technical challenges are automated fixture generation, role-based access control, and reliable notification delivery. 
Thus, we can say that this project is technically feasible.

2.	Economic Feasibility

SpotFix would be economically feasible; the only costs associated with our project are development costs, database hosting, and third-party notification services. This could be reduced if we are provided access from the university’s side to host the database and also use email services instead. 
In terms of limitations, as of now, the limitation would be finding the team’s time and technical ability on the project for the initial deployment. The further limitation would be in the future, if we have to expand this system further with other features and make it on a commercial scale.

3.	Operational Feasibility

As of now, our stakeholders involved can do the same process of our proposed system manually; however, this involves multiple risks of human error and makes it much less efficient. Instead, SpotFix intends to fix this by centralizing all these activities in one platform. So that league administrators to manage their teams, players, schedules, scores, and standings, while team owners can register and manage their teams and players.
Thus, by using our system, it is expected to reduce administrative workload, improve the accuracy and availability of league information, and give users a more convenient way to interact with the league. Since our proposed system intends to solve the current problem, it is supposed to be operationally feasible.
In regards to the acceptance of the system, we can obtain feedback from users in order to improve the usability and simplicity of the application. 

4.	Schedule Feasibility

Based on the current available remaining course duration, we believe that this project should be completed by the end of the course, considering that we do proper designation and active communication within the team. The issue, as mentioned before, would be finding the time for the entire team and the coordination of various aspects through git and also ensuring that we are all on the same page.
The project will be implemented throughout the duration of the semester; thus, each week we will be able to complete a different part of the project. 

5.	Overall Feasibility

Based on the technical, economic, operational, and schedule feasibilities, SpotFix is considered a feasible project to develop within the available course duration. The required technologies are accessible to us, and the project can be developed using existing software.
The overall project will, in turn, benefit the stakeholders mentioned above so that they can have ease of access to the community sports league. It should make all the proceedings to make an event smooth.
The key constraints are the short development timeline and the difficulty of implementing a dependable automated scheduling system. If the system is developed beyond the prototype stage, third-party services such as SMS notifications may add to the costs.
Overall, the project can be completed within the course timeframe if the jobs are appropriately distributed among team members and enough time is set aside for testing and debugging.
